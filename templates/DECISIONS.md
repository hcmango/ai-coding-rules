# 决策与避坑记录

这个文件用来记录项目里已经拍板的架构选择，以及明确否决过的方案。开新会话准备做大改动或提新方案前，先读一遍，避免重复讨论已经走不通的路。

## 已拍板的决策

### D01 · 决策标题（例如：前期暂不建独立官网，用 GitHub 主页承接）

- **日期**：`YYYY-MM-DD`
- **结论**：写清最终决定。
- **原因**：写清当时面临的真实约束和取舍依据。
- **重新评估条件**：写明达到什么阶段或条件后，才值得重新讨论这个决定。

## 被否决的方案与踩过的坑

| 方案或踩过的坑 | 为什么不行 | 实际采用的替代做法 |
| :--- | :--- | :--- |
| 从零搭建大而全的通用工作台 | 范围容易失控，开发周期拉得过长，迟迟上不了线 | 先只做一个每天自己真在用的核心功能模块 |
| 单元测试直接依赖本机默认时区 | 在东八区跑得通，放到 UTC 环境的 CI 或海外机器上就会失败 | 在时间计算和格式化函数里显式传入 `Calendar` 或 `TimeZone` |
| 在多个规则文件里复制同一套说明 | 改完一处很容易漏掉另一处，不同工具读到的要求会互相打架 | 只在 `AGENTS.md` 维护一份正文，其他工具入口只留一句引用 |
