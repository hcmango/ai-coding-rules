# 项目级 AGENTS.md 模板

将本文件复制到业务仓库根目录，改名为 `AGENTS.md`。这里只写这个仓库里模型猜不到的本地事实、联动关系和验收方式，不堆泛化的编码口号。

## 项目概况

- **项目说明**：用一句话写清这个项目做什么、给谁用。
- **技术栈与常用命令**：写明语言、框架、包管理器，以及本地开发、测试和构建命令。

## 目录分工

每类代码和文档放在固定位置，避免在多个地方维护同一份定义：

| 路径 | 负责什么 |
| :--- | :--- |
| `src/schemas/` | 对外接口的数据结构和类型定义，作为唯一定义来源 |
| `src/services/` | 核心业务逻辑和外部接口封装 |
| `src/pages/` 或 `src/views/` | 页面编排与渲染，不在这里堆复杂业务逻辑 |
| `docs/DECISIONS.md` | 历史决策和被否决的方案，提大改动前先读 |

## 联动更新要求

改了左列的内容后，必须同步检查并更新右列，避免只改一处导致代码或文档对不上：

| 当你修改了 | 必须同步核对并更新 |
| :--- | :--- |
| 接口字段或数据结构 | 类型定义 → 服务端实现 → 调用方 → 对应单元测试 |
| 环境变量或启动依赖 | `.env.example` → `README.md` 里的启动说明 |
| 目录结构或核心模块边界 | 本文件 `AGENTS.md` 中的目录分工 |
| 既有架构方案或踩出新坑 | 追加记录到 `docs/DECISIONS.md` |

## 不要手动修改的区域

- 构建产物和缓存目录（如 `dist/`、`.next/`、`.build/`、`node_modules/`）。
- 依赖锁文件（如 `pnpm-lock.yaml`、`package-lock.json`），除非本次任务明确要求调整依赖。
- 与当前任务无关的历史模块和文档。

## 修改后的验证顺序

1. 查看 `git diff`，确认改动局限在当前任务范围内。
2. 运行类型检查、单元测试和生产构建，确认没有报错。
3. 涉及页面或交互变化时，在真实运行环境里核对效果，不能只看编译通过。

如果这是一个桌面或 macOS 客户端项目，可以额外补上下面两条：

- **新旧版本切换**：构建失败时保留正在运行的旧版本；构建成功后先按进程名退出旧实例，再通过本次构建产物的绝对路径启动新版，并检查实际窗口和布局，不靠模糊应用名打开其他位置的旧副本。
- **保护本地数据**：调试、测试和截图时使用隔离的临时配置或预览数据，不要覆盖用户本机的真实数据。
